## Where the shared libraries go

PRD D1 says the libraries `lti`, `moodle_ws` and `model_interface` belong to the first release that uses
them, not to Release 0, and that the Release 0 notes list where each one goes. `contracts` and `media_paths`
are Release 0 libraries and are not listed here.

| Library | First release | First user | Source |
|---|---|---|---|
| `model_interface` and the speech interface (FR-M-01, FR-M-02) | Release 3 | Video (FR-V-04, FR-V-05, FR-V-06) | Guide, [issue #112, comment 7221502371](https://github.com/narenccode/learnops/issues/112#issuecomment-7221502371), items 8 and 9. The PRD edit is pull request #259 (check that it has merged before relying on the PRD text) |
| `moodle_ws` | **Release 1** | Course Checker, **course lookup only** | Module 2 owner's confirmation of 28 November 2026 on the guide's question (item 9 of the comment above); PRD C2.6 ("B4 (course lookup)"); `docs/design/checker.md` section 4 and 6.1 |
| `lti` | The first release that uses it | Course Checker (mentor interface, FR-C-09, Release 1) and the other web modules | PRD D1; `docs/decisions/0001-lti-library.md`. Outside the Student 2 Release 0 completion count |

**Scope of the Release 1 `moodle_ws` dependency.** The Checker calls `moodle_ws` only for the B4 course
lookup (`core_course_get_courses_by_field`, by course id or shortname) that binds an LTI context to a Moodle
course (PRD B3 course binding). It does **not** use `moodle_ws` to build the B2 course model: the model comes
from a course package or a `.mbz` backup. No other Moodle web-service call is added for the Checker, and this
note changes no contract or LTI code. The later releases that use more of `moodle_ws` (for example Grading)
are listed by their own owners.

**Not verified here.** `libs/moodle_ws` is not on `main` yet, and the B4 lab checks (App-C item 1, decision
0019) are about B4 on Moodle 5.3, not about this dependency.
